What it does

What Ridgeline Ontology gives the operation.

Semantics

Every object, property and link written down once, in the words the business uses. A repair ticket and a service order resolve to the same work order, for a person and for an agent.

Kinetics

Lifecycles say which states a record can be in and which moves are allowed. The server enforces them: no screen, script or agent can skip a step.

Functions

The numbers the operation runs on, computed in one place and callable by name by any application or agent.

Roles decide who sees which object, property and action. An agent sees exactly what its role allows, and nothing it was never granted.

In depth

Ontologies are to agents what databases are to people

A database assumes a reader who already knows what the columns mean, remembers what changed last year and reconciles two systems in their head. An agent has none of that. Give an agent a database and it guesses; give it an ontology and it resolves.

Three layers, in the right order

The systems of record are never replaced, modified or migrated; each connects through an adapter. Ridgeline Ontology is one model above them, a projection rather than a copy. Applications and agents read meaning from the model, never from the silos, so a question that crosses silos comes back with citations.

Four verbs make it living

Nouns become objects, facts become properties, relationships become typed links, and actions change them. The system senses as data lands, decides as questions are answered, acts as approved decisions write back, and learns as the outcome lands again. A model that is only read is a report; a model that is read, acted on and updated is an operating system for the organisation.

Treat the ontology as a codebase

Every application exports its ontology as a typed manifest beside the code that enforces it. The customer's engineers review it, version it and run it like any other part of the stack. Built on open standards (RDF, OWL, SPARQL and SHACL) and exposed to agents through MCP, so there is no lock in.

Where it runs

The ontology, its data and its agents run where the customer's data lives: on premises, in a private cloud or air gapped, on models the customer hosts. Publish, and the whole system exports as code.

Questions

Questions about Ridgeline Ontology.

What is the difference between an ontology and a database for agents?

A database assumes a reader who already knows what the columns mean. An ontology writes that meaning down once, as objects, properties, typed links and actions, so an agent resolves instead of guessing.

Do we have to replace our systems?

No system of record is replaced, modified or migrated. Each connects through an adapter, and the ontology sits above them.

Who owns it?

The customer. The ontology, its rules, its agent endpoint and its applications export as code into the customer's own repository.
